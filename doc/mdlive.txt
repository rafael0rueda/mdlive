1. INTRODUCTION                                 *mdlive* *mdlive-introduction*

mdlive shows a live preview of a Markdown buffer in your browser. The preview
updates while you type, follows your cursor and uses the colors of your
colorscheme.

The HTTP server runs inside Neovim and every browser library is bundled with
the plugin, so there is nothing else to install and it works offline.

==============================================================================
2. REQUIREMENTS                                          *mdlive-requirements*

- Neovim 0.11 or newer
- A web browser

==============================================================================
3. INSTALLATION                                          *mdlive-installation*

With lazy.nvim: >lua
    {
      "rafael0rueda/mdlive",
      ft = "markdown",
      cmd = { "MdLive", "MdLiveStop", "MdLiveToggle", "MdLiveExport" },
      opts = {},
    }
<
Calling |mdlive.setup()| is optional: the commands work with the defaults.

==============================================================================
4. COMMANDS                                                  *mdlive-commands*

:MdLive                                                              *:MdLive*
    Starts the preview of the current buffer and opens it in the browser.
    If a tab is already connected to the buffer, only its URL is shown.
    With |mdlive-follow|, an open tab switches to the current buffer instead
    of a new tab being opened.

:MdLiveStop                                                      *:MdLiveStop*
    Stops the preview of the current buffer. The browser tab shows that the
    preview stopped. In a buffer without a preview, it stops every preview,
    such as the one following you with |mdlive-follow|.

:MdLiveToggle                                                  *:MdLiveToggle*
    Starts or stops the preview of the current buffer.

:MdLiveExport[!] [file]                                        *:MdLiveExport*
    Writes the preview of the current buffer to a standalone HTML file, with
    styles, fonts and diagrams included. [file] defaults to the buffer's
    file with an `.html` extension. With [!], an existing file is
    overwritten. The page is rendered by the browser, so a preview tab is
    opened first if none is connected. See |mdlive-export|.

------------------------------------------------------------------------------
MAPPINGS                                                     *mdlive-mappings*

mdlive maps no keys. Each command has a Normal mode mapping that you can bind
to your own keys.

<Plug>(MdLive)                                                *<Plug>(MdLive)*
    Same as |:MdLive|.

<Plug>(MdLiveStop)                                        *<Plug>(MdLiveStop)*
    Same as |:MdLiveStop|.

<Plug>(MdLiveToggle)                                    *<Plug>(MdLiveToggle)*
    Same as |:MdLiveToggle|.

<Plug>(MdLiveExport)                                    *<Plug>(MdLiveExport)*
    Same as |:MdLiveExport| without [file] or [!].

Example: >lua
    vim.keymap.set("n", "<leader>mv", "<Plug>(MdLiveToggle)",
      { desc = "Markdown live preview" })
<

5. CONFIGURATION                                        *mdlive-configuration*

Pass options to |mdlive.setup()|. These are the defaults: >lua
    require("mdlive").setup({
      host = "127.0.0.1",
      port = 0,
      browser = nil,
      debounce_ms = 150,
      auto_open = false,
      filetypes = { "markdown" },
      follow = true,
      scroll_sync = true,
      follow_theme = true,
      code_line_numbers = true,
    })
<
Unknown options and options of the wrong type are reported with a warning, and
the wrong ones keep their default. `:checkhealth mdlive` lists them too.
Calling |mdlive.setup()| again also updates previews that are open.

host                                                      *mdlive-config-host*
    Type: `string`, default: `"127.0.0.1"`
    Address the server binds to. Keep it on a loopback address: the preview
    also serves the files next to your Markdown.

port                                                      *mdlive-config-port*
    Type: `integer`, default: `0`
    Port of the server. `0` picks a free port.

browser                                                *mdlive-config-browser*
    Type: `nil`, `string`, `string[]` or `fun(url: string)`, default: `nil`
    Opens the preview. `nil` uses the system default browser through
    |vim.ui.open()|. A string such as `"firefox"` or a list such as
    `{ "firefox", "--new-window" }` is run with the URL appended. A function
    receives the URL.

debounce_ms                                        *mdlive-config-debounce_ms*
    Type: `integer`, default: `150`
    Milliseconds to wait after the last change before updating the preview.

auto_open                                            *mdlive-config-auto_open*
    Type: `boolean`, default: `false`
    Starts the preview when a buffer with one of the `filetypes` is opened.

filetypes                                            *mdlive-config-filetypes*
    Type: `string[]`, default: `{ "markdown" }`
    Filetypes used by `auto_open` and `follow`.

follow                                                  *mdlive-config-follow*
    Type: `boolean`, default: `true`
    Uses a single tab that follows the buffer you are in. See |mdlive-follow|.

scroll_sync                                        *mdlive-config-scroll_sync*
    Type: `boolean`, default: `true`
    Scrolls the preview to follow the cursor.

follow_theme                                      *mdlive-config-follow_theme*
    Type: `boolean`, default: `true`
    Uses the colors of the current colorscheme in the preview. When `false`,
    the preview uses a light or dark theme based on the browser settings.

code_line_numbers                            *mdlive-config-code_line_numbers*
    Type: `boolean`, default: `true`
    Shows line numbers on code blocks with more than one line. They are left
    out when copying the code and when printing. Double-click a number to
    move the cursor to that line.

6. LUA API                                                        *mdlive-api*

The functions are in the `mdlive` module. Where they take a buffer, `0` means
the current buffer. Errors are returned and also shown with |vim.notify()|.

mdlive.setup({opts}?)                                         *mdlive.setup()*
    Sets the options, see |mdlive-configuration|. Only needed to change them.

    Parameters: ~
      - {opts}?  (`table`) Options to change.

mdlive.enable({enable}?, {filter}?)                          *mdlive.enable()*
    Starts or stops previews. |:MdLive| is `enable(true, { buf = 0 })`.

    Examples: >lua
        local mdlive = require("mdlive")
        -- Stop every preview.
        mdlive.enable(false)
        -- Toggle the preview of the current buffer.
        vim.keymap.set("n", "<leader>mv", function()
          mdlive.enable(not mdlive.is_enabled({ buf = 0 }), { buf = 0 })
        end, { desc = "Markdown live preview" })
<
    Parameters: ~
      - {enable}?  (`boolean`) `true` (the default) starts, `false` stops.
      - {filter}?  (`table`) With the field:
                   - {buf}? (`integer`) Buffer, `0` for the current one.
                     Without it, `false` stops every preview and `true`
                     previews the current buffer.

    Return (multiple): ~
        (`true?`) `true` on success.
        (`string?`) Error message on failure.

mdlive.is_enabled({filter}?)                             *mdlive.is_enabled()*
    Tells whether a buffer is being previewed.

    Parameters: ~
      - {filter}?  (`table`) With the field:
                   - {buf}? (`integer`) Buffer, `0` for the current one.
                     Without it, tells whether any buffer is previewed.

    Return: ~
        (`boolean`)

mdlive.export({bufnr}?, {opts}?, {callback}?)                *mdlive.export()*
    Same as |:MdLiveExport| for {bufnr}. The browser renders the page, so
    the file is written later; {callback} reports the result.

    Example: >lua
        -- Export the current buffer next to its file, then open the result.
        require("mdlive").export(0, nil, function(err, path)
          if not err then
            vim.ui.open(path)
          end
        end)
<
    Parameters: ~
      - {bufnr}?     (`integer`) Buffer, `0` or `nil` for the current one.
      - {opts}?      (`table`) With the fields:
                     - {path}? (`string`) File to write, by default the
                       buffer's file with an `.html` extension.
                     - {force}? (`boolean`) Overwrites an existing file.
      - {callback}?  (`fun(err: string?, path: string?)`) Called once, when
                     the file is written ({err} is `nil`) or the export
                     fails.

    Return (multiple): ~
        (`true?`) `true` when the export started.
        (`string?`) Error message when it could not start, for example
        when the file exists and {force} is not set. {callback} gets it too.

------------------------------------------------------------------------------
DEPRECATED FUNCTIONS                                       *mdlive-deprecated*

These functions still work, show a warning once and will be removed in
mdlive 1.0.

mdlive.open({bufnr}?)                                          *mdlive.open()*
    Use |mdlive.enable()|: `enable(true, { buf = bufnr })`.

mdlive.close({bufnr}?)                                        *mdlive.close()*
    Use |mdlive.enable()|: `enable(false, { buf = bufnr })`.

mdlive.toggle({bufnr}?)                                      *mdlive.toggle()*
    Use |mdlive.enable()| and |mdlive.is_enabled()|:
    `enable(not is_enabled({ buf = bufnr }), { buf = bufnr })`.

mdlive.is_open({bufnr}?)                                    *mdlive.is_open()*
    Use |mdlive.is_enabled()|: `is_enabled({ buf = bufnr })`.

7. FEATURES                                                  *mdlive-features*

Live update                                               *mdlive-live-update*
    The buffer is sent to the browser while you type, without saving. Only
    the parts of the page that changed are updated, so images and diagrams do
    not flicker. If Neovim quits, the tab stops reconnecting after a few
    attempts; click the status message to try again.

Follow mode                                                    *mdlive-follow*
    With `follow` enabled, the connected tab switches to the Markdown buffer
    you enter, for example with |:edit|, |:buffer| or by changing windows.
    Buffers of other filetypes, floating windows and special buffers (such
    as LSP hover popups) are ignored, so the preview stays where it is.

Scroll sync                                               *mdlive-scroll-sync*
    The preview shows the same part of the document as the Neovim window
    and keeps the block under the cursor in view. Scrolling without moving
    the cursor, such as with CTRL-E or the mouse wheel, scrolls it too.

Jump to source                                                   *mdlive-jump*
    Double-click a block in the preview to move the Neovim cursor to the
    line it comes from.

Theme                                                           *mdlive-theme*
    Colors come from highlight groups such as |hl-Normal|, `@markup.heading`,
    `@keyword`, `@string` and `@comment`, and are sent again when the
    colorscheme or 'background' changes.

Markdown                                                     *mdlive-markdown*
    CommonMark with tables, strikethrough, task lists, heading anchors,
    footnotes and `:emoji:` shortcodes. Code blocks are highlighted and have
    line numbers (see |mdlive-config-code_line_numbers|) and a copy button,
    `$inline$` and `$$block$$` math is rendered with KaTeX, and ```mermaid
    code blocks are drawn as diagrams.

GitHub alerts                                                  *mdlive-alerts*
    A blockquote starting with `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`,
    `[!WARNING]` or `[!CAUTION]` is shown as an alert, colored with the
    |hl-DiagnosticInfo|, `DiagnosticOk`, `DiagnosticHint`, `DiagnosticWarn`
    and `DiagnosticError` highlight groups.

Front matter                                             *mdlive-front-matter*
    YAML (`---`) or TOML (`+++`) front matter at the top of the file is shown
    as a collapsed block.

Links and images                                                *mdlive-links*
    Relative images, including `<picture>` sources and `<video>` or `<audio>`
    files, are loaded from the directory of the Markdown file. Clicking a
    relative link to a Markdown file opens that file in Neovim and the tab
    shows its preview. Links to other local files open the raw file in a new
    tab, keeping a fragment such as `#page=3` for PDFs, and web links open in
    a new tab.

Export                                                         *mdlive-export*
    |:MdLiveExport| saves the page as it looks in the preview, theme colors
    included, as a single HTML file that needs no network. Relative images
    and links are rewritten to work from where the file is saved. For a
    PDF, print the preview from the browser; the copy buttons and status
    messages are left out of the printout.

8. SECURITY                                                  *mdlive-security*

Markdown can contain raw HTML, for example in a README of a repository you
just cloned, so the preview treats it as untrusted:

- The HTML is sanitized with DOMPurify, and a Content-Security-Policy only
  allows the plugin's own scripts, so embedded scripts never run. Attributes
  the page uses for its own features are removed from it, so a web link
  cannot pose as a link that opens a file in Neovim.
- Files are served only from the directory of the Markdown file and the
  current working directory, in a sandbox that blocks scripts. Symlinks are
  resolved first, so a link cannot point outside those directories.
- Preview URLs contain a random token, new each time the server starts, and
  every request for the page, its events, files or actions needs it. Other
  users or programs on the machine cannot read your buffers or files through
  the server. Files are only served for buffers that are being previewed.
- The server rejects requests with a non-local Host header. Requests that act
  in Neovim (opening a linked file, moving the cursor, saving an export) must
  come from the preview page itself, so other websites cannot send them.
- Exported HTML files include a Content-Security-Policy that blocks scripts
  wherever they are opened.
